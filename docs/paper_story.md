# 논문 스토리 — JKICS 확정판 (2026-07-10, 풀 캠페인 반영)

> 투고처: **JKICS(한국통신학회논문지)**. 프레이밍: **task-oriented LiDAR 데이터(대역폭) 저감**.
> 근거 데이터: Gazebo/PX4 + SUPER, **seeds 1~11 × 5 runs × 3 modes = 165런** (results/campaign_full_seeds1-11_x5.csv).
> 과거 탐색 과정·폐기 가설은 `연구일지.md`와 이전 버전(git history) 참조.

---

## 1. 제목(안)

**"자율 비행 UAV의 LiDAR 데이터 저감을 위한 속도-정렬 적응형 섹터 필터링"**
(Velocity-Aligned Adaptive Sector Filtering for LiDAR Data Reduction in Autonomous UAVs)

## 2. 서론 — 왜 대역폭인가

1. 360° LiDAR(Livox Mid-360)는 ~20만 점/초 ≈ 25–30 Mbps 생성; 고밀도 센서는 수백 Mbps.
2. UAV는 이 데이터를 **무선으로 전송/오프로딩**하는 경우가 많음: 지상국(GCS) 모니터링·원격 매핑, SWaP 제약에 따른 엣지/클라우드 오프로딩, 스웜의 공유 채널 점군/지도 교환.
3. 무선 링크는 제한·가변적(WiFi 실효 수십 Mbps, LTE/5G 업링크 수 Mbps~, 거리·간섭·NLOS) → LiDAR 원시 스트림이 링크를 포화시키면 지연·손실 → 실시간 제어 위험.
4. 전송 에너지 ∝ 데이터량 → 배터리 비행시간과 직결.
5. → **태스크 지향(task-oriented) 저감**: 항법 태스크에 필요한 방향(진행방향) 데이터만 유지하고 나머지를 버림. (task-oriented/semantic communication 흐름과 정합)
- 정직 단서: 필터는 **전송/처리 데이터량**을 줄이는 것(센서 생성량 아님) → 동기를 전송/오프로딩/스웜 시나리오에 명시적으로 겨눔.

## 3. 제안 기법

1. **수평 섹터 필터**: 점군을 수평 ±60°(=120°) 콘으로 절단. 콘 밖 240° 폐기.
2. **속도-정렬 적응형(velocity-aligned adaptive)**: 콘 중심을 기체 기수(heading)가 아니라 **속도(진행방향)** 에 정렬 — 저역통과 + 최근 확신 진행방향 유지로 저속/회전 전이 안정화. 태스크 관련 데이터(가는 방향)를 항상 유지.
3. **safety-assured planner(SUPER)와 통합**: 필터 출력(`/cloud_registered`)을 SUPER(ROG-Map+CIRI+backup 궤적)가 소비. C++ 노드(cloud_preprocessor), 런타임 토글.
4. (부차) **플래너 레벨 FoV-awareness**: SUPER FOVChecker에 수평 ±각 cut 구현(원저자는 OMNI 고정) — 미감지 방향을 unknown으로 취급해 감지 축소의 대가를 충돌이 아닌 보수화로 전환. ±60° 과보수(기어감)/±90° 완주의 trade-off 정량화(native 시뮬).

## 4. 실험 (헤드라인 숫자 — 11맵 × 5런 × 3모드 = 165런)

랜덤 장애물 숲 11종(seed 1~11: 크기·밀도 축), 4-코너 페리미터 루프, PX4 SITL + SO3 컨트롤러, 모드당 55런.

| 지표 | full(360°) | sector(고정±60°) | **adaptive(속도정렬±60°)** |
|------|-----------|------------------|---------------------------|
| 점/frame | 8414 | 2974 (**64.6%↓**) | 2990 (**64.5%↓**) |
| 매핑 raycast (ms/frame) | 1.75 | 0.61 (**65.1%↓**) | 0.63 (64.1%↓) |
| ROG 총 매핑 (ms/frame) | 6.60 | 2.92 (**55.7%↓**) | 3.16 (52.1%↓) |
| 충돌/런 | 1.53 | 0.95 (**38%↓**) | 0.93 (**39%↓**) |
| min clearance (m) | 0.33 | 0.43 | 0.40 |
| **완주율** | 82% | 85% | **95%** |
| 미션 시간(성공런) | 136s | 122s | 133s |

### 결과 해석 (3-포인트)
1. **데이터 64.6% 저감** — 전 seed에서 robust(57~69%), 저감의 기하학적 예측(120°/360°=67%)과 일치.
2. **매핑 비용 감소는 raycasting 기반 맵에서 발생**(raycast 65%↓, 총 매핑 56%↓). 프레임당 매핑 시간이 일관된 연산 지표(CPU%는 편차 커 보조로만, ~9%↓).
3. **저감이 안전을 해치지 않을 뿐 아니라 개선**: full-view는 dense 필드에서 ROG-Map을 과밀 점유시켜 계획 품질을 열화 → 충돌 최다(1.53). sector/adaptive는 충돌 38~39%↓ + clearance 개선. **adaptive는 저감을 유지하면서 완주율 최고(95% vs full 82%)** — 콘이 항상 진행방향을 덮어 계획 정체가 적음.

## 5. 논의·한계 (정직)

- **적용 경계**: (i) 동적 장애물 — 폐기한 240°에서 접근하는 이동체는 감지 불가, 본 기법 부적합. (ii) 다방향 감지 미션(벽면 검사 등) — 단일 콘 부적합. (iii) 정적 장애물 + 전진 비행이 유효 영역.
- **연산 이득의 조건**: raycasting/occupancy 매핑을 쓸 때 매핑 비용이 점 수에 비례해 감소. raycasting-free 플래너(SUPER 기본 모드)에서는 연산 이득 없음 — 이득의 본질은 **전송 대역폭**.
- 충돌 수치는 SO3 컨트롤러 트래킹 오차가 포함된 **모드 간 상대 비교**(세 모드 동일 조건).
- 시뮬레이션 한정(PX4 SITL), 정적 환경, 완주율·충돌은 런 간 편차 존재(전체 순서는 유지).

## 6. 기여 요약

1. 360° LiDAR 점군의 **수평 섹터 필터링으로 전송 데이터 64.6% 저감** (11맵 165런 실증).
2. **속도-정렬 적응형** 콘 정렬 — 저감 유지 + **최고 완주율(95%)** + 최저 충돌.
3. raycasting 기반 매핑 비용 55~65% 저감 및 **full-view 과밀 점유에 의한 계획 열화** 현상 규명 — "언제 FoV 축소가 유효한가"의 실용 가이드(정적○/동적×/raycasting○/raycasting-free×).
4. (부차) safety-assured planner의 수평 FoV-awareness 구현과 보수화 trade-off 정량화.
