# 배경 고정 원기둥 후보 5개 — K02~K06 (2026-09-15)

## 승인 범위와 맵

사용자 요청: 실험을 계속하며 맵5개를 만든다. K01의 배경/외곽 원기둥과
레일을 유지하고 내부 장애물 배열·크기·간격만 변경한다. planner, 센서,
필터/Adaptive 알고리즘, v7, ±45°, 미션 loop24,180초 제한, ACK retry0 및
자원 기준은 동결한다. 모든 장애물은 항상 존재하는 높이3 m의 정적 원기둥이다.
맵 이름/PCD 경로 이외의 simulator YAML 설정은 K01과 같다.

| 새 맵 | 내부 변경 | 총 원기둥 | 변경 장애물 지름(m) | 축방향 열 간격(m) | 기하 경로 최소 body 여유(m) |
|---|---|---:|---:|---:|---:|
| K02 | 잘라냈던 교차 열 끝을 복원, 열마다5개 | 536 | 0.80 | 5.0 | 0.4533 |

모두 외곽126개와 기존 배경을 그대로 보존한다. 위 열 간격은 모든 원기둥의
최근접 간격이 아니다. K03의 같은 열 내 최소 표면 간격은0.04 m, 나머지
맵은약0.20 m다. 접하지 않는 원기둥이더라도 촘촘한 열은 기체가 통과할 수
없는 경계를 만들 수 있으므로, 이를 희박한 자연 숲의 대표 사례라고 부르지
않는다. 전체 맵에 대해 겹침 없음과 오프라인 기하 우회 경로를 확인했다.
경로는 planner에 공급되지 않으며 dynamics/실제 완주 보장이 아니다.

K01의 세 모드 모두3/3 성공 결과를 보고 설계한 관련 탐색군이다. 최종
성과 맵5개가 확보됐다는 뜻이 아니며, 독립 blind/held-out 배치도 아니다.
기존 Normal/J05/K01/실패 후보 데이터는 삭제하거나 수정하지 않는다.

## 사전 지정한 시험 순서와 중단 규칙

1. K02→K03→K04→K05→K06 각각 Full/Sector/Adaptive 한 번씩(초기15회).
2. 첫 묶음에서 Full 또는 Adaptive가 안전 완주하지 못한 후보는 이후
   반복에서 제외한다. 다만 해당 묶음의 세 모드는 마치고 실패를 보존한다.
3. 나머지 후보는각3회/모드까지 확대한다. 2회차순서 S/A/F,3회차 A/F/S.
   새로운 기준 모드 실패도 묶음을 마친 뒤 그 후보만 더 반복하지 않는다.
   따라서 최대45회이며 중단 후보를 맵당3회 완료로 표시하지 않는다.
4. 자원/계측 invalid면 전체 진단을 멈춘다. 자동 재시도로 실패를 지우지
   않는다. 살아 있는 observer에서 ACK가0개인 경우는 실제 입력 정체일 수
   있으므로 단순히 invalid로 제외하지 않는다.
5. Sector의 ACK 장기 침묵을 따로 집계한다. 단순 empty-cloud 정지를
   장애물 회피 우위로 바꾸어 해석하지 않는다. 모드 차이가 나더라도
   원인/trajectory audit 후에야 표준 프로토콜의 새 n20로 넘어갈 수 있다.
   이번 실행기는 n20를 자동 시작하지 않는다.

5개 첫 비교는약35~60분, 전부3회까지 진행하면약1시간30분~2시간30분을
예상한다. 실패180초 제한과 resource preflight 대기 시간에 따라 더 늘어날
수 있다. 단일 비행이며 시험 중 맵 생성/빌드/대규모 git 작업을 하지 않는다.

## 계측과 파일

기존 prelaunch solid-cylinder observer 및 별도 읽기 전용 ACK observer를
사용한다. 이 추가 계측 결과는 진단 전용이며 기존 n20 또는 논문 CPU표에
합치지 않는다. ACK는 K01과 같이 원래 종료 시각까지의 값과10초 warmup 뒤
실제 목표 도착까지의 값을 함께 보존한다. K01에서 도입한 종료 경계 보완을
이5개 맵에서는 비행 전에 정했다. 실패는 마지막 odometry 경계를 사용하며
종료 처리 시간이 포함될 수 있음을 표시한다.

기존 trajectory audit은 맵 전체가 아니라 지정한 첫 feature 원기둥 한 개를
본다. audit0을 모든 장애물의 risk0으로 해석하지 않는다. 접촉은 맵 전체
원기둥과 실제 표본 pose로 검사하며 연속 swept/dynamics 보장은 아니다.

- 생성기: `scripts/native_campaign/cylinder_background_variants.py`
- 실행기: `scripts/native_campaign/run_cylinder_background_five.py`
- 맵/기하: `results/cylinder_map_search_20260914/cyl2_k02`부터`cyl2_k06`
- 전체 계획/상태: `results/cylinder_background_five_20260915/{plan,status}.json`
- 개별 원자료/요약: 같은 폴더의`cyl2_kNN/{diagnostic_raw.csv,summary.json}`
- PCD/YAML: SUPER runtime에서 생성 후 대응 mirror 파일로 복사 완료.
- 새 계측·기하·재개 규칙을 포함한 집중 테스트25개 통과.

실행 명령:

```bash
cd /root/super-sector-filter
PYTHONNOUSERSITE=1 python3 -u scripts/native_campaign/run_cylinder_background_five.py
```

이미 실행 중이면 중복 시작하지 않는다. `status.json`과 실제 PID를 함께
확인하며, 계획 파일/맵/동결 코드가 다르면 기존 결과에 이어 쓰지 않는다.
