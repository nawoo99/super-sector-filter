# C24 Normal 5맵 결과: OFF 75회 / ON 15회 (2026-09-17)

## 1. 결론과 표본

`c24_iteration01`의 Normal 5맵 × Full/Sector/Adaptive × 모드별 5회, **본시험 75회를 모두 완료했다.**
각 모드는 25/25 완주, 접촉 발생 주행 0/25이며 재시도·회차 교체는 없었다.
계측 ON 사전시험 15회는 별도 표본이며 본시험 CPU 평균에 섞지 않았다.
별도의 정적 사전검증은 DDS 30건과 실제 RViz 5건이다.

Full 대비 Adaptive의 본시험 전체 평균 CPU 감소는 **35.53%**, 주행당 누적 CPU 감소는 **33.13%**다.
맵 입력 논리 payload는 67.20%, 맵 갱신 경과시간은 62.24% 감소했고,
평균 주행시간은 42.02초에서 43.67초로 3.92% 증가했다.
처음 요청한 평균 CPU 40% 감소는 이번 전체 결과와 각 맵 평균에서 **미달성**이다.
35.53%를 40% 달성으로 바꾸어 해석하지 않는다.

Sector 역시 모든 주행에서 완주·접촉 0이므로, 이 Normal 시험만으로 Adaptive의
Sector 대비 안전성 우위를 주장할 수 없다. 관측된 100% 완주는 이 후보와 이 75회에
한정되며, 다른 환경·반복 전체의 100% 보장을 뜻하지 않는다.

후보와 고정 입력, 정적 검증, 중단 기준은 [C24 검증 계획](c24_normal_validation_20260917.md)을 따른다.
비동기 certified recovery는 이 캠페인에서 세 모드 공통으로 명시적으로 켰으며 기본값은 OFF다.
이전 [C23의 실패·미완료 17시도 기록](c23_normal_comparison_20260916.md)은 보존하고 새 75회와 합산하지 않는다.

## 2. 맵별 본시험 결과

CPU 범위는 실험 cgroup의 시뮬레이터·frontend·planner·mission·launcher 합계이며 외부 측정기는 제외한다.
시뮬레이터와 planner가 같은 프로세스이므로 순수 planner CPU로 표기하지 않는다.

`PC 전체 기준 실험 CPU(%) = 평균 사용 코어 수 / 20 논리 CPU × 100`이다.

## 3. Full 대비 감소율

`감소율 = 100 × (1 − 대상 모드 평균 / 같은 맵 Full 평균)`.
각 셀은 **Sector / Adaptive** 순서다. 마지막 행은 모드별 25회 평균끼리의 비율이며,
위 다섯 감소율을 다시 산술평균한 값과는 다르다.

| 맵 | 평균 CPU 감소 S / A | 누적 CPU 감소 S / A | 맵 입력 논리 payload 감소 S / A | 맵 갱신 경과시간 감소 S / A |
|---|---:|---:|---:|---:|
| N1 (seed1) | 33.65% / 30.95% | 30.43% / 29.44% | 71.57% / 69.74% | 63.86% / 62.76% |
| N2 (seed3) | 40.82% / 39.09% | 39.32% / 39.79% | 73.24% / 72.09% | 66.92% / 65.19% |
| N3 (seed5) | 40.28% / 37.43% | 40.88% / 34.34% | 73.44% / 67.24% | 65.66% / 61.94% |
| N4 (seed7) | 41.12% / 35.50% | 37.54% / 34.44% | 71.87% / 66.92% | 68.35% / 61.88% |
| N5 (seed9) | 41.58% / 34.05% | 39.53% / 28.39% | 73.33% / 63.93% | 68.04% / 59.56% |
| 전체 25회/모드 | 39.74% / 35.53% | 37.98% / 33.13% | 72.79% / 67.20% | 66.68% / 62.24% |

논리 payload는 `map_payload_mib_s`이고, 측정 맵 프레임의 바이트를 주행시간으로 정규화한
지표다. 프레임 수집 구간과 주행 구간은 완전히 같지 않으며 물리 네트워크·PCIe·메모리
대역폭 측정이 아니다. frontend와 map 경계에 같은 버퍼가 기록되더라도 합산하지 않았다.
맵 갱신은 `total_ms_mean` 경과시간이며 CPU 시간과 같지 않다. 중첩된 하위 단계와 합산하지 않는다.

평균 CPU는 시간당 비용이고 누적 CPU는 측정 구간 전체 비용이다. 예를 들어 N5 Adaptive는
Full보다 평균 주행시간이 9.21% 길어, 평균 CPU 감소 34.05%에 비해 누적 감소는 28.39%다.
주행시간은 사전 계획대로 결과 지표로 보존했으며, 느린 회차를 제거해 감소율을 올리지 않았다.

## 4. 실제 Adaptive 전환과 복구

아래는 각 맵 5회 **합계**다. 연속 소스 프레임의 `full` 상태 변화와 원본 복구 audit를
대조했으며, 초기 주행 준비 중 복구도 포함한다. legacy risk-engine의 switch 카운터가 아니다.

양방향 전환 합계는 160회이고 복구 cycle은 80회다. **80회가 80번의 충돌 회피를 뜻하지 않는다.**
Full/Sector의 실제 시야 전환은 각 0회다. 이 표는 Adaptive의 관측 시야 복구 cycle이며,
세 모드 공통 planner의 비동기 복구 요청·결과 횟수와는 별도 집계다.

## 5. 전체 평균과 PC 사용률 구분

각 모드는 동일한 5맵에서 25회다. 아래 PC 전체 CPU는 배경 프로그램을 포함한 시스템 측정값이며,
baseline은 각 주행 전 별도 관측 평균이다. 두 값을 빼서 알고리즘 비용으로 주장하지 않는다.

| 모드 | 주행시간 (s) | 평균 CPU (cores) | 실험 CPU / PC 용량 | 누적 CPU (core-s/회) | PC 전체 CPU (배경 포함) | 주행 전 baseline CPU |
|---|---:|---:|---:|---:|---:|---:|
| Full | 42.0208 | 0.695767 | 3.4788% | 30.806336 | 10.4362% | 7.4522% |
| Sector | 43.4560 | 0.419273 | 2.0964% | 19.105610 | 9.2455% | 7.6657% |
| Adaptive | 43.6700 | 0.448593 | 2.2430% | 20.601576 | 9.4090% | 7.6927% |

본시험의 실험 전체 sampled peak RSS 평균은 Full/Sector/Adaptive 순으로
3465.92 / 3450.97 / 3459.29 MiB이며, 같은 peak PSS 평균은
3426.57 / 3411.65 / 3419.91 MiB다. RSS 합계는 공유 페이지를 중복 계산할 수 있다.
GPU 측정은 배경 작업을 포함한 장치 전체 값이며 planner만의 GPU 비용이 아니다.
GPU·메모리·CPU p95/max·단계별 지연·포인트 수·센서 주파수 등의 모든 수치와 결측 여부는 아래 전체 보고서에 남겼다.

이번 본시험에는 메모리 보호 중단, OOM, stack 채집에 의한 계측 오염 marker가 없었다.
그러나 새 방어 코드가 C23의 메모리 증가 원인이었던 함수를 고쳤다는 증거는 아니다.
원래 실패의 stack을 확보하지 못한 한 원인 확정과 재발 미관측은 구분한다.
