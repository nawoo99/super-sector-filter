## 지속 실행과 판정 규칙

실행기: `scripts/native_campaign/cylinder_feedback_search.py`.

1. 새 맵을 불변 이름으로 생성하고 동결정책/자산 및 우회 경로를 확인한다.
2. 추가 ACK observer가 있는3모드 진단을최대3묶음 실행한다. 기준모드
   실패 또는 장기 입력 정체가 나오면 해당 묶음을 마친 뒤 새 맵으로 간다.
   부분 묶음으로 중단됐다가 재개하는 경우에는 남은 모드부터 마친다.
3. Full/Adaptive가 진단3회 모두 안전 완주하고 Sector에서 실제 차이가
   나오면, **추가 ACK observer 없는 표준 solid 계측으로 새3묶음**을 시행한다.
   추가 계측 진단을 표준 개발/n20 행으로 이름만 바꾸거나 합치지 않는다.
4. 표준 개발도 통과하면 기존 확인 실행기를 통해 **새run101~120/모드**로
   20회 검증한다. Full/Adaptive 실패 시 묶음 끝에서 중단·보존·재설계한다.
5. 선정은 Full20/20·Adaptive20/20 안전 완주, Sector 실제 실패/접촉,
   Sector 최소1회 완주 및 단순 empty-input 정체가 아닌 실패 양상이 있는
   경우다. Sector가 전부 빈 입력으로 멈추는 맵은 성과로 세지 않는다.
6. 조건을 충족한 서로 다른 맵5개가 확보되면 종료한다. 후보 횟수 제한은
   두지 않는다. 사용자 중단 또는 실제 계측/무결성/저장공간/인프라 문제는
   중단 사유와 원자료를 남긴다. 정책을 임의로 완화해 계속하지 않는다.

진단의 입력 정체 분류는 empty경고100회 이상 + 실제 pose정지20초 이상 +
ACK간격5초 초과다. 표준 계측에는 추가 ACK observer가 없으므로 앞의
로그·pose 조건을 proxy로 사용하고 이를 분명히 표시한다. 개별 오류의
완전한 인과 증명이나 모든 위험 탐지 여부를 대체하지 않는다. 기존
trajectory audit은 지정 원기둥1개에만 적용되므로0건을 전체맵 risk0으로
해석하지 않는다. 접촉0은 표본 pose에서의 관측값이지 연속 swept/dynamics
안전 보장이 아니다.

확인 결과를 보고 맵을 다시 선정하는 **결과 의존적 탐색**이다. 탈락/중단
횟수와 모든 실패를 공개한다. 통과한20/20을 모집단100% 보장이나 독립
holdout 검증으로 쓰지 않는다. 최종600행의 재사용/계측 일치 여부는 별도다.
